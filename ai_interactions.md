# AI interactions

This project was built with the help of generative AI, as the challenge allows. This file states which tools were used, how, and which parts of the code they generated.

## Tools

- **Claude Code** (Anthropic, Claude Opus model) in the terminal alongside WebStorm: planning, code generation, running checks and git operations.
- **OpenSpec**: spec-driven workflow. Each feature was first written as a change (proposal, specs, design, tasks) and reviewed before any code; completed changes are archived in `openspec/changes/archive/` and their specs live in `openspec/specs/`.

## How AI was used

The AI worked as an assistant, not as the driver:

- **Step by step:** for every task the AI proposed the approach, I approved or adjusted it, the AI implemented it, and I reviewed the diff and commit message before committing. Each OpenSpec task is exactly one commit.
- **Decisions were mine:** the AI presented options and trade-offs; I chose. Examples:
  - Lightweight Clean Architecture instead of the full pattern (proportionate to an MVP).
  - `scrypt` (built into Node) over bcrypt for the mock password hashes.
  - Validating the RUT check digit, even though the statement's example RUT is invalid.
  - A hash-based deterministic score; I compared it against an alternative MD5-based snippet and kept SHA-256 without duplicated normalization.
  - A CORS allowlist instead of a dev proxy; brief tests; small Conventional Commits with short bodies.
- **Transparency in history:** AI-assisted commits carry a `Co-Authored-By: Claude` trailer.

## What the AI generated

| Area                                               | AI involvement                                                                                                                                                            |

| **Frontend (`frontend/`)**                         | **Fully AI-generated.** My background is backend, so I delegated the React code entirely and validated every scenario manually in the browser.                            |

## Verification and corrections

- Every commit passes lint, format check, type check, tests and build; endpoints and UI flows were also exercised manually.
- The modulo 11 RUT check-digit algorithm came from the AI's general knowledge (not from a cited source); it is covered by unit tests and a hand-computed example.
- Course corrections I asked for along the way: plans that were too detailed for an MVP, tasks bundled into too-large commits (split into one commit per task) and overly long commit bodies. Questioning the RUT algorithm also surfaced a terminology error in the code ("module-11" instead of "modulo 11"), which was fixed.
